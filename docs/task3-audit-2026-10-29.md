## Reproduced and repaired

- **False saved success:** `save_returned` plus invented stat returned
  `applied_full` while disk still contained `old`. Receipt verification now reads
  the actual pinned target, checks root/canonical path/stat and independently
  compares decoded text and optional raw encoded hash. A matching disk hash alone
  cannot bless different uploaded logical text. Save policy and dirty final
  state cannot be bypassed. No-op files do not increase `files_applied`.
- **Lost results on teardown:** source abort/session/application retirement
  rejected already issued receipts, and cancellation discarded verification
  results. The actual issued artifact and reservation now survive until worker
  and journal join. Exact retired owners may settle facts, never acquire rights.
  Verification uses the already reserved worker slot; admission cannot deadlock
  at the global capacity ceiling.
- **Fabricated editor facts:** `written` used the requested string rather than
  post-change-hook text. Delete did not recheck after its guard callback and
  always claimed a closed buffer even when kill queries refused. Actual text,
  buffer lifetime and guarded source facts are now recorded; observation failure
  remains explicit.
- **Receipt transport:** eager chunk copies had no aggregate bound and ignored
  negotiated frame limits. The cursor now bounds files/parts/aggregate bytes,
  freezes observations before yielding and produces one UTF-8 chunk per ACK.
  File/part/offset/completion/terminal ACKs are validated. Cancellation preserves
  receipt settlement; malformed ACK or build failure drains the old connection
  without replay or a stranded physical writer fence.
- **Formal coverage:** the issuance model lacked the new verification worker.
  It now models verification join followed by separate terminal IO, retains
  ownership through both, and forbids positive completion without verification.

Regression evidence is in `tests/editor_receipt.rs` (10 real native pipe tests,
including eight false-success cases and three retirement paths),
`test-native-edit-document.el` (18 tests), `test-native-edit-activity.el` (14),
and `test-native-edit-transaction.el` (3). The positive native fixtures now really
write files and capture real stat evidence instead of inventing successful data.

## Remaining limits

1. Native hunk counts, rollback body retention/stack and foreign-version guarded
   rollback, revised Ediff, actual tool/LSP/verification readers and legacy
   deletion still need implementation and their own end-to-end regressions.
2. Native saved receipt validation supports the decoder's actual encodings.
   A live editor coding that native cannot confirm yields partial/unknown;
   a generic encoding attestation must not turn a client hash into proof.
3. Full batch receipt responses are not paged for tiny negotiated frames.
4. Real Emacs 1 KiB startup fails at the existing unpaged `provider/catalog`
   hydration response. The 1 KiB edit receipt fixture retains the real native
   handshake/scope and isolates only provider hydration. It does not establish
   general 1 KiB application startup. This is tracked as todo 3.18.
