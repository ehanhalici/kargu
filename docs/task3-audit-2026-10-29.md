`.codex/01_RUST_CORE_PATTERNS.md`. **Task 3 remains open.** Native revision,

on connection readiness or mocked functions, and a selected operation never

## Reproduced and repaired in this review

- **Foreign rollback ownership:** the proposed inverse captured the current disk
  as if it belonged to the agent. It now compares against the exact stat/canonical
  path recorded by the verified receipt before preparing an inverse. Actual
  foreign disk writes before preparation are rejected, including edits whose
  original save hook transformed their body.
- **Incorrect inverse/history:** saved additions now invert to deletions; deleted
  files invert to additions. The inverse base is the actual retained final body,
  including save-hook output. Successful inverse files consume only their original
  history entries. They never create redo snapshots. Earlier matching versions
  receive the new owned document/disk identity so consecutive undos remain valid.
  Owned dirty buffer-only edits can be undone without saving; native metadata
  restores their original clean state and coding. Current review/save/config/
  policy inputs are captured afresh, rather than reusing old consent.
- **Unbounded or resurrected history:** snapshots have an application-wide count
  limit of 16 and a conservative original-plus-final body limit of 48 MiB.
  Retirement prevents late receipts from resurrecting closed-session history.
  Passive consumer references also retain only sixteen recent observed edit IDs.
  References confer no rights; Rust can evict them sooner.
- **Non-atomic revision:** the source artifact was changed before the permission
  update and budget validation could fail. Candidate text, artifact and action
  now share immutable bodies prepared on a bounded worker. Temporary bytes are
  reserved before dispatch. Only a successful source adoption consumes the gate's
  infallible revision permit. Failure preserves both old records; cancellation
  retains the candidate reservation and worker until actual join. Review metadata,
  digest and revision advance together. File indices and text use domain types.
- **Actor IO:** rollback filesystem capture moved into the existing read-worker
  admission, cancellation, timeout and join path. Revision hashing also runs on
  its reserved worker, rather than blocking the application actor.
- **Synchronous/reentrant producer:** production `accept-process-output` loops
  were removed. Metadata and text pages are fully read before issuance, document
  observations are retained through preflight and actual primitive entry, and
  source/session/mode revision/policy ownership is checked on continuations.
  A stale second document prevents entry into the first file. Local file-variable
  evaluation is disabled when opening captures. Target directories never become
  implicit authorization roots.
- **Lost journal durability:** the producer no longer deletes successful journals
  with a per-operation temporary directory. It uses a private persistent directory
  outside the edited workspace; tests provide their own disposable directory.
- **Partial review and unsafe dispatch:** reviewing the first file no longer
  authorizes unseen batch files. Revised decisions and errors are honored, the
  next presentation waits for Ediff cleanup, and only owned controls are closed.
  Native undo references always use the exact edit ID/root/file and cannot enter
  legacy rollback when disconnected or when the opt-in setting changes. Mixed
  native/legacy history requires an explicit single-step boundary.
- **Invented results:** whole-file, revised and inverse hunk counts are explicitly
  unmeasured (`null` on the wire, `:json-null` in consumer DTOs). Original patch
  counts remain available where valid; hook-transformed applied counts become
  unknown. Saved facts come from receipts. Opaque legacy summaries remain unknown;
  no `APPLIED:` prefix is treated as a typed result. Only actual applied/partial
  files enter the changed-file projection, with a fresh identity for each edit.
- **Process regression:** replacing shared legacy Git process supervision with
  raw `make-process`/`delete-process` was reverted. The bounded/cancellable shared
  runner remains until that consumer is fully migrated.

The earlier receipt audit repairs are retained: native disk/body verification,
retired-owner settlement without renewed write rights, actual editor observations,
bounded receipt upload/ACK handling and the cross-epoch physical writer fence.

## Remaining limits

1. Full consumer/default cutover, verification/change-reader migration and legacy
   deletion remain separate work. Merely connecting the core cannot select the
   new writer. Native tool calls require asynchronous callbacks.
2. Actual hunk measurement for whole-file writes, human revisions and inverse
   proposals remains unimplemented; unknown counts never masquerade as zero or one.
3. Native saved receipt verification supports the decoder's actual encodings.
   Unsupported live codings can yield partial/unknown; a client hash alone is not
   evidence of the relationship between logical text and disk bytes.
4. Large batch receipt responses are not paged for tiny negotiated frames. The
   paged preparation test at 4 KiB is not a promise that every receipt fits every
   negotiated frame. Outcomes that cannot be delivered must not be replayed.
5. Real Emacs 1 KiB startup still fails at unpaged `provider/catalog` hydration
   (todo 3.18). Small edit fixtures isolate hydration while retaining the native
   handshake and scope.
6. Native rollback bodies are process-local. Persistent journals retain outcome
   evidence, rather than granting replay rights or reconstructing an undo stack
   after restart. Journal retention/recovery policy and full GUI cancellation/
   foreign-window acceptance remain part of the open migration work.
