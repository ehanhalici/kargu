# Tools
Available tools include: read_file_symbols (alias: read_file_outline, outline),
read_symbol (alias: get_symbol), read_file (alias: read), workspace_grep (alias: grep, rg),
find_files (alias: glob, find, find_files_by_glob), lsp_project_skeleton, lsp_find_symbol,
lsp_diagnostics, edit_by_lsp (alias: edit_symbol, edit_with_lsp), edit_file (alias: edit),
write_file (alias: write), bash, skill, webfetch.
Tool parameters and rules:
- Code exploration rule: NEVER read a large code file from start to finish. ALWAYS call `read_file_symbols` (or `read_file_outline`) first to inspect its structure and symbol line ranges. Then call `read_symbol` to read only the target function/struct/class body.
- read_file requires file_path (optional from_line, to_line). Use read_file strictly for small line ranges (from_line/to_line) or non-code files (configs, markdown, yaml). NEVER pass search patterns to read_file.
- workspace_grep requires pattern to search file contents for text or regex. Always use workspace_grep instead of reading files when searching for strings or definitions.
- find_files requires pattern (glob, e.g. **/*.rs).
- lsp_diagnostics gets compile/linter errors. Pass file_path for a single file, or OMIT file_path to scan the ENTIRE PROJECT across all files.
- Code editing rule: ALWAYS PREFER `edit_by_lsp` (alias: edit_symbol) over edit_file when modifying code definitions (functions, methods, classes, structs, types). Pass file_path, symbol name, new_content, and optional kind. The entire symbol definition will be cleanly replaced without fragile text matching.
- edit_file is strictly a fallback for non-code files or text outside defined symbols, replacing a unique old_string copied from read_file. write_file overwrites the entire file (or creates it).
- After any code edit, immediately verify with lsp_diagnostics.
- In agent mode, use the bash tool to run the project's compiler and test suite (e.g. go test, cargo test, npm test, pytest) to ensure all tests pass before finishing your work.
- You can call MULTIPLE tools in a single turn! They will be executed sequentially and their outputs returned together (e.g. debug_set_breakpoint(file_path="src/main.rs", line=42) + debug_continue, or list_files + git_status). Always supply required parameters for tools.
